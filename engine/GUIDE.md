## 1. 실행하고 고치기

엔진은 `engine/src/`의 자바스크립트 파일 묶음입니다. 서버를 띄우고 `dev.html`을 열면 파일을 하나씩 불러오므로, 고치고 새로고침하면 바로 보입니다.

```bash
python -m http.server 8765
```

브라우저에서 `http://localhost:8765/engine/dev.html`을 엽니다.

**예시 1-1. 숫자 하나 바꿔 보기.** `src/02_config.js`에서 하루의 길이를 12분에서 2분으로 줄입니다.

```js
sky: {
  dayLength: 120,           // 720 → 120
```

새로고침하면 해가 눈에 보이게 움직입니다. 같은 파일에서 차의 무게(`car.mass`), 접지력(`car.grip`), 중력(`phys.gravity`), 눈 쌓이는 속도(`weather.snowRate`), 블룸(`post.bloom`)도 같은 방식으로 바꿉니다.

**예시 1-2. 주소로 상태 정하기.** 코드를 고치지 않고 장면을 고정해 볼 수 있습니다.

| 주소 뒤에 붙이기 | 결과 |
|---|---|
| `?mode=drive&day=17.5&still` | 해질녘에 멈춘 시간, 운전 모드 |
| `?weather=snow&day=9` | 아침, 눈 |
| `?mode=actors&day=16&weather=clear` | 정원에서 사람을 직접 조작합니다. WASD·방향키 또는 왼쪽 터치 스틱으로 걷고, 화면을 끌어 카메라를 돌립니다. |
| `?wet&weather=clear&day=16.6&still` | 비가 갠 오후. 표면이 먼저 마르고 낮은 곳에 고인 물이 뒤이어 빠짐 |
| `?look=plain` | 기본 조명만(라이팅 비교용) |
| `?low` | 가벼운 설정(그림자 해상도, 안티에일리어싱 낮춤) |

**예시 1-3. 배포용 한 파일 만들기.** 새 파일을 추가했거나 웹에 올릴 때 한 번 돌립니다.

```bash
python tools/build.py
```

`index.html`(전부 합친 한 파일)과 `dev.html`(파일 목록)이 다시 만들어집니다. Windows에서는 앞에 `PYTHONUTF8=1`을 붙입니다.

## 2. 세계를 바꾸기

세계는 세 가지로 이뤄져 있습니다: 땅(`42_island.js`), 하늘과 날씨(`10_sky.js`, `41_weather.js`), 그 위에 놓인 것들.

**예시 2-1. 날씨와 시각을 코드에서 정하기.** 브라우저 개발자 도구의 콘솔에 그대로 칩니다.

```js
Weather.set('snow');     // clear | rain | snow | frost | auto
G.day = 6.5;             // 시각 (0~24). 6.5는 해 뜰 무렵
```

게임 안에서는 같은 줄을 규칙에 넣으면 됩니다(예: 3바퀴째에 비가 오기 시작).

**예시 2-2. 땅에 대해 묻기.** 눈에 보이는 땅, 바퀴, 물리가 모두 같은 함수를 씁니다.

```js
const [height, kind] = Island.surf(x, z);   // kind: 0 아스팔트, 1 갓길, 2 풀밭, 3 모래
const road = Island.nearRoad(x, z);         // road.d: 도로까지 거리, road.i: 도로의 몇 번째 점
```

**예시 2-3. 산의 모양 바꾸기.** `42_island.js`의 `Hb(x, z)`가 높이 함수입니다. 능선 높이를 정하는 `105`를 `160`으로 바꾸면 산이 더 험해지고, 도로와 등산로는 새 지형 위에 다시 깔립니다.

**예시 2-4. 새 재질에 날씨 입히기.** 직접 만든 물체의 재질에 눈이 쌓이게 합니다.

```js
const m = new THREE.MeshStandardMaterial({ color: 0x8a5a3a });
patch(m, s => {
  s.fHead(GLSL_NOISE + GLSL_WX);
  s.f('#include <color_fragment>', `#include <color_fragment>
    diffuseColor.rgb = mix(diffuseColor.rgb, vec3(.87, .9, .95), wxCover(vFogW, .8));`);
}, 'my-roof');
```

`wxCover(월드좌표, 위를 향한 정도)`가 그 자리의 적설량(0~1)을 돌려줍니다.

**예시 2-5. 비 갠 뒤의 노면과 접촉 음영 비교하기**

[해안 도로 고정 시점](https://hahyuck.github.io/bee-garden/engine/?wet&weather=clear&day=16.6&still&cam=-415.647,12.942,-139.209,-424.934,10.75,-139.007,62,.11)에서 `L` 패널의 **젖은 노면**을 누릅니다. 평지에서는 낮은 바퀴 자국을 따라 하늘이 길게 비칩니다. 경사에서는 물이 고이는 면적이 줄어듭니다. `CFG.surface`의 `fillTime`과 `drainTime`은 웅덩이가 차고 빠지는 속도(초)를 정합니다.

**접촉 음영**은 카메라의 깊이 버퍼에서 가까운 표면끼리 가리는 부분을 찾아 초점·블룸 처리 전에 반영합니다. `CFG.post.contactRadius`는 탐색 반경의 상한(미터), `contactStrength`는 강도입니다. 일반 설정에서는 주변 깊이를 최대 12번, `?low`에서는 4번 읽습니다. 카메라에서 멀어져 탐색 반경이 한 픽셀 정도가 되면 효과가 사라집니다.

**노출 적응**은 하늘의 밝기와 적설량을 따라갑니다. 안내의 **한밤으로**를 실행한 뒤 이 스위치를 누르면, 눈이 어둠에 익숙해지는 동안 밝기가 어떻게 변하는지 비교할 수 있습니다.

## 3. 물리와 효과 쓰기

물리는 이미 돌아가고 있습니다. 물체를 놓기만 하면 중력, 충돌, 부력, 바람이 적용됩니다.

**예시 3-1. 물체 놓기.**

```js
Phys.prime(x, z);                                    // 그 자리의 땅을 단단하게 (멀리 놓을 때)
Phys.spawn('crate', x, y, z);                        // crate | barrel | cone | stone
Phys.spawn('stone', x, y, z, { v: { x: 0, y: 5, z: 20 } });   // 던지기: 초속도 지정
```

**예시 3-2. 새 종류 추가.** `85_phys.js`의 `KIND`에 한 줄을 더합니다. 아래는 지름 1m의 가벼운 공입니다.

```js
ball: { n: 60, geo: () => new THREE.SphereGeometry(.5, 24, 16), col: c => c.ball(.5),
        rho: 80, fr: .6, re: .7, vol: .52, r: .5, area: .8, tint: 0xe84a3a },
```

`rho`는 밀도(물은 1000이라 80이면 물에 뜹니다), `re`는 튀는 정도, `vol`은 물에 잠기는 부피, `area`는 바람을 받는 넓이입니다.

**예시 3-3. 폭발과 띠.**

```js
Phys.blast(x, y, z);                 // 주변 물체를 날리고, 껍질·고리·불꽃을 그리고, 주변을 잠깐 밝힘
FX.trail(a, b, 0.3, 0);              // a에서 b까지 띠 한 조각. 0 먼지, 1 물보라, 2 불꽃
LightField.hot(x, y, z, 60);         // 그 자리에 뜨거운 빛
```

**예시 3-4. 매 스텝 내 힘 넣기.** 차가 이 방식으로 바퀴의 힘을 넣습니다. 아래는 모든 통을 위로 살짝 띄우는 예입니다.

```js
Phys.pre.push(h => {
  for (const e of Phys.bodies) if (e.kind === 'barrel' && e.on)
    e.b.applyImpulse({ x: 0, y: e.b.mass() * 12 * h, z: 0 }, true);
});
```

## 4. 게임 규칙 넣기

게임은 "모드" 하나로 만듭니다. 모드는 들어올 때 할 일(`enter`), 나갈 때 할 일(`leave`), 매 프레임 할 일(`step`)을 가진 객체입니다. `step`이 카메라를 놓고, 규칙을 검사하고, 화면 아래에 보일 한 줄을 돌려줍니다.

**예시 4-1. 통 모으기(전체 코드).** `src/89_example_collect.js`에 들어 있고, `0` 키로 시작합니다. 노란 통 10개를 60초 안에 날아가서 모으는 게임입니다.

```js
const Collect = (() => {
  const N = 10, TIME = 60; let items = [], score = 0, left = 0, best = 0;

  function enter() {                               // 새 판: 주변에 통 10개를 놓는다
    score = 0; left = TIME; const p = Modes.fly.p; items = [];
    for (let i = 0; i < N; i++) {
      const a = i / N * TAU, r = 14 + 22 * Math.random(), x = p.x + Math.cos(a) * r, z = p.z + Math.sin(a) * r;
      Phys.prime(x, z, 0);
      items.push(Phys.spawn('barrel', x, Math.max(Island.surf(x, z)[0], 0) + 1.5, z, { color: 0xffd040 }));
    }
  }

  function step(camera, dt) {
    Modes.MODES.free.step(camera, dt);             // 이동은 자유 비행을 빌려 쓴다
    if (left > 0) {
      left -= dt;
      for (const e of items) {                     // 규칙: 2.6m 안에 들어오면 얻는다
        if (e.got) continue; const q = e.b.translation();
        if (camera.position.distanceTo(q) < 2.6) { e.got = true; score++; FX.blast(q.x, q.y, q.z, 3); e.b.setTranslation({ x: q.x, y: -100, z: q.z }, true); }
      }
      if (score === items.length || left <= 0) { best = Math.max(best, score); left = 0; }
    }
    return left > 0 ? `통 모으기 ${score} / ${items.length} · 남은 시간 ${left.toFixed(0)}초` : `끝! ${score}개 · 최고 ${best}개`;
  }

  Modes.add('collect', { name: '통 모으기', enter, leave() {}, step }, 'Digit0', '0');   // 모드 등록: 이름, 키
})();
```

게임에 필요한 네 가지가 다 들어 있습니다: 자기 모드, 물리 세계에 놓인 물체, 매 프레임 검사하는 규칙, 화면에 보이는 한 줄.

**예시 4-2. 입력 읽기.** 눌린 키는 `Modes.keys`에 있습니다.

```js
if (Modes.keys.has('Space')) jump();
```

게임패드는 `87_drive.js`의 `readInput()`이 본보기입니다(표준 배치의 버튼과 스틱).

**예시 4-3. 저장하기.** 브라우저에 남깁니다. 차의 최고 랩 기록이 이렇게 저장됩니다.

```js
localStorage.setItem('mygame.best', String(best));
best = +localStorage.getItem('mygame.best') || 0;
```

**예시 4-4. 심도를 쓰는 카메라.** 모드의 `step` 안에서 초점 거리와 조리개를 정합니다.

```js
Post.lens.focus = 3;        // 3m에 초점
Post.lens.aperture = 40;    // 0이면 심도 없음. 사람 크기의 장면은 30~80, 벌처럼 몇 cm 앞을 볼 때는 1 안팎
Post.lens.focus = 0;        // 0으로 두면 화면 가운데에 자동으로 초점을 맞춤
```

## 5. 이 엔진을 게임 엔진으로 활용하는 방법

### 5-1. 무엇을 이미 갖고 있나

| 게임에 필요한 것 | 엔진에 있는 것 | 상태 |
|---|---|---|
| 세계 | 섬(지형 함수, 도로, 등산로, 숲), 바다, 하늘, 시간, 날씨 | 있음 |
| 빛과 화면 | 해·달, 그림자, 안개, 빛 필드, 빛기둥, 블룸, 톤 곡선 | 있음 |
| 물리 | 강체, 충돌, 부력, 바람, 폭발, 광선 검사 | 있음 |
| 탈것 | 차(서스펜션, 타이어, 변속), 추격 카메라, 랩 계측 | 있음 |
| 카메라 | 자유 비행, 걷기(등산로 따라), 추격, 보닛 | 있음 |
| 입력 | 키보드, 게임패드 | 있음 |
| 소리 | 바람·파도·비·엔진·충돌(합성) | 있음, 음악과 녹음된 소리는 없음 |
| 캐릭터 | 다섯 사람 중 하나를 조종해 걷기, 대기와 보행 혼합, Froggy의 추적 도약 | V 캐릭터 모드 |
| 외부 모델 | 사람을 골라 조종하고 소품·건물·자동차·비행기를 정원에 놓아 관찰 | 오른쪽 샘플 메뉴 |
| 적과 동료 | 길 찾기, 행동 | 없음 |
| 화면 UI | 메뉴, 체력 바, 미니맵, 대화창 | 한 줄 표시와 일시정지 화면만 |
| 저장 | 진행 상황 | 최고 기록 정도만 |
| 여러 명 | 네트워크 | 없음 |

### 5-2. 장르별로 무엇을 더하면 되나

**3인칭 레이싱** — 가장 가깝습니다. 차, 코스, 랩 타임, 날씨에 따른 접지력이 이미 있습니다.
- 더할 것: 경쟁 차(도로의 점을 따라가는 조종), 출발 신호와 순위, 체크포인트.
- 시작점: `87_drive.js`의 조향·가속 입력에 사람 대신 계산값을 넣으면 경쟁 차가 됩니다.

**1인칭 슈팅** — 던지기(`F`)와 폭발(`X`)이 이미 발사와 피격의 뼈대입니다.
- 더할 것: 땅을 걷는 1인칭 몸(지금은 날아다님), 표적과 체력, 조준점, 무기 반동.
- 시작점: `Phys.ray(카메라 위치, 보는 방향)`으로 맞은 곳을 구하고, 그 자리에 `Phys.blast`를 부르면 즉시 맞는 총이 됩니다.

```js
const cam = G.camera, dir = cam.getWorldDirection(new THREE.Vector3());
const hit = Phys.ray(cam.position, dir, 200);      // 보는 방향으로 200m까지
if (hit) Phys.blast(hit.x, hit.y, hit.z, 300, 3);
```

**3인칭 비행 시뮬레이션** — 하늘, 바다, 섬, 바람이 있고 물리에 힘을 넣는 길(`Phys.pre`)이 있습니다.
- 더할 것: 비행기 몸체와 양력·항력 계산, 비행 카메라, 계기.
- 시작점: 차가 바퀴 힘을 넣듯, 날개의 양력을 속도 제곱에 비례해 넣습니다. Pixel Aleste의 응결 고리와 비행운은 이때 가져올 수 있게 남겨 뒀습니다.

**3인칭 MMORPG** — 가장 멉니다. 세계와 날씨, 시간은 쓸 수 있지만 핵심이 빠져 있습니다.
- 플레이어 조작, 전투 애니메이션, 서버 동기화, 인벤토리·퀘스트·대화, 대규모 월드 스트리밍은 별도 제작이 필요합니다.
- 현실적인 첫걸음: 혼자 하는 작은 RPG 한 구역(마을 하나, 퀘스트 하나, 적 한 종류). 여러 명은 그 뒤입니다.

### 5-3. 대화로 만드는 방법

이 엔진은 사람이 코드를 다 쓰는 것이 아니라, 원하는 것을 말하면 Claude가 해당 파일을 고치는 방식으로 자랐습니다. 요청이 구체적일수록 결과가 좋습니다.

| 이렇게 말하면 | 이렇게 됩니다 |
|---|---|
| "차가 너무 미끄러워" | `02_config.js`의 접지력 값을 조정 |
| "밤에 전조등이 켜지게 해 줘" | `87_drive.js`에 조명 추가, 시각에 따라 켜짐 |
| "해안 도로에 헤어핀을 두 개 넣어 줘" | `42_island.js`의 도로 찾기를 수정 |
| "통 모으기를 통 대신 꽃으로, 벌 시점으로 바꿔 줘" | 예시 게임을 복사해 새 모드 작성 |
| "이 GLB를 정상에 놓아 줘" | `89_vr_actors.js`의 로딩과 높이 정렬을 참조해 해당 모드에서 배치 |

요청할 때 도움이 되는 것:
- **보이는 것을 말하기**: "나무가 어색해"보다 "가지 끝이 보라색으로 보여"가 빨리 고쳐집니다.
- **기준을 주기**: 참고할 게임이나 장면, 화면 캡처.
- **한 번에 한 덩어리**: 물리, 날씨, 구조를 한꺼번에 바꾸면 무엇이 문제인지 찾기 어렵습니다.
- **직접 해 보고 말하기**: 조작감, 소리, 실제 속도감은 사람이 해 봐야 알 수 있습니다. 자동 검사는 숫자와 정지 화면까지만 봅니다.

### 5-4. 엔진의 강점으로 키울 세 가지

1. **대화로 하는 월드 빌딩** — 세계를 코드가 아닌 데이터 파일 하나로 적어서, "북쪽 곶에 등대"라는 말이 파일의 몇 줄로 바뀌게 합니다. 지금은 배치가 코드 안에 있어서 아직 안 됩니다.
2. **준비된 물리** — 물체에 "움직인다, 무게는 얼마"라고만 적으면 충돌체가 붙게 합니다. 물리 자체는 이미 있습니다.
3. **GLB를 받는 환경** — 불러온 모델에 크기 맞춤, 지면 배치, 그림자, 충돌체, 눈 쌓임을 자동으로 입힙니다.

세 가지는 같은 배치 데이터를 쓰므로 한 묶음으로 만드는 것이 맞습니다. 이것이 다음에 할 일입니다.

### 5-5. 알고 써야 할 한계

- 브라우저에서 도는 엔진입니다. 언리얼이나 유니티 같은 편집기, 에셋 파이프라인, 콘솔 출시 경로는 없습니다.
- 숲과 산의 큰 형태는 코드로 만들고, 바위와 흙의 표면에는 실측 텍스처를 씁니다. 사람과 동물은 제작자가 배포한 VRChat 아바타를 GLB로 변환해 읽습니다.
- 빛은 근사입니다. 빛을 추적하는 전역 조명이 아닙니다.
- 섬 하나 크기(약 1km)에 맞춰져 있습니다. 더 넓은 세계는 지형을 흘려 넣는 방식부터 다시 짜야 합니다.
- 성능은 가벼운 설정(`?low`)에서만 확인했습니다.
